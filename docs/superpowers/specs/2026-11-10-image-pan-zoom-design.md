# Image & diagram pan/zoom — design

Issue: [#49 SVG viewing needs ability to zoom](https://github.com/brucevanhorn2/viewmaster/issues/49)

## Intent

Large diagrams are unreadable at fit-to-pane size. The triggering case is a
database schema `.svg` generated by [tbls](https://github.com/k1LoW/tbls)
with many tables and fields: zoomed out, the text is illegible. The app-wide
**Zoom In** (Electron window zoom) scales the entire UI, so it doesn't help.

The way the user actually reads such a diagram is **map-style**: zoom into one
corner, then drag the view around to follow relationship lines from table to
table. Success = they can open that schema in View Master and comfortably
trace a relationship across it without leaving the app.

## Goals

- Pan & zoom for every image View Master shows:
  - standalone `.svg` files (rendered view)
  - standalone raster images (`content.kind === 'image'`: PNG, JPG, etc.)
  - mermaid diagrams inside rendered markdown
  - images inside rendered markdown **that actually load** (see "Markdown
    images" below)
- Controls that feel like most desktop apps:
  - **Ctrl+wheel** zooms, anchored at the mouse pointer (the point under the
    cursor stays under the cursor).
  - **Click-drag** pans.
  - **Plain wheel** scrolls vertically; **Shift+wheel** scrolls horizontally
    (standalone images).
- A small control cluster, top-right: **−**, current zoom **%**, **+**, **Fit**.

## Decided behavior

### Standalone images (`.svg` and raster)

- Fill the content pane, as today.
- Open at **Fit** (whole image visible, same as current `max-width/height:
  100%; object-fit: contain` look). Never upscaled past 100% at Fit for
  images smaller than the pane — _builder's call whether small images open at
  100% or "fit"; keep today's appearance._
- Controls are always visible.
- Plain wheel / Shift+wheel pan the view when zoomed in.
- Switching to another file resets to Fit. Zoom level is **not** remembered
  per file.
- **Same file reloaded from disk** (the existing `refreshKey` reload, e.g. the
  user regenerates the schema with tbls): **keep** the current zoom and pan.
  Key the reset on the file path, not on the content.

### Images and mermaid diagrams inside markdown (option A: zoom in place)

- The diagram stays in the document flow, inside its own box. It is _not_
  popped out to a separate viewer.
- **Ctrl+wheel over the diagram** zooms it within its box; **drag** pans
  within the box.
- **Plain wheel always scrolls the page**, never the diagram — the reader must
  never get trapped inside a diagram while scrolling through a doc.
- The box keeps the diagram's natural rendered size at Fit (no layout jump on
  load). Zooming in does not grow the box; the content is clipped to it.
- Controls appear **on hover** over the diagram.
- Applies in both `MarkdownView` and both panes of `MarkdownSideBySideView`.
- **Side-by-side: each diagram zooms independently.** Zoom/pan is _not_
  mirrored across the old and new panes (existing scroll sync is unaffected).
- **Same doc reloaded from disk:** the markdown body and mermaid re-render, so
  zoom state must live outside the injected DOM. Restore each diagram's
  zoom/pan **by its index in the document** (1st zoomable, 2nd, …) when the
  number of zoomable elements is unchanged; otherwise reset all to Fit.
  Switching to a different file resets everything.

### Markdown images

Images referenced from markdown (`![](diagram.svg)`) **do not load today**:
the renderer CSP is `img-src 'self' data:` and nothing resolves relative
`src` against the `.md` file. Making them load (path resolution + CSP/
protocol changes) is **out of scope** and will be filed as a separate issue.
This work only attaches pan/zoom to markdown `<img>` elements that do render
(e.g. `data:` images); once that separate fix lands, markdown images get
pan/zoom automatically with no further work here.

### Zoom range & rendering

- Range: from Fit up to about **800%**. Below Fit is not needed.
- SVGs (standalone and mermaid) must stay **crisp** at every zoom level —
  scale the vector, don't rasterize and upscale. Raster images simply scale.
- **Fit** button returns to the initial fit state and recenters.

### Unchanged

- The app-wide Zoom In / Zoom Out / Reset menu commands keep working exactly
  as now (whole-window zoom).
- SVG **Source** (`mode === 'code'`) view is unaffected.
- The existing mermaid pipeline (`runMermaidIn`, its serialized queue and
  error styling) is unaffected except for wrapping successful output.

## Non-goals

- No lightbox / pop-out viewer (option B was considered and declined).
- No fixing of markdown image loading (separate issue).
- No zoom/pan synchronization between side-by-side panes.
- No minimap, rotate, measure, or export.
- No persistence of zoom/pan across file switches or app restarts.
- No zoom for PDFs (`PdfView`), HTML view, or code views.
- No pinch/trackpad-specific gesture work beyond what Ctrl+wheel events
  already deliver (browsers report trackpad pinch as Ctrl+wheel, which is
  fine to get for free).

## Anti-goals (failure even if it "works")

- Plain wheel in a markdown doc gets captured by a diagram and stops page
  scrolling.
- SVG text goes blurry when zoomed.
- The whole UI scales (that's the bug being fixed).
- Diagrams in docs jump size or reflow when they load or when hovered.

## Constraints

- Renderer is React 19 + TypeScript in `src/renderer/src`; tests are vitest
  (`npm test`), typecheck via `npm run typecheck`. Follow existing patterns.
- Markdown HTML is injected via `dangerouslySetInnerHTML`; mermaid replaces
  `pre.mermaid` contents with an `<svg>` asynchronously after render. Pan/zoom
  for in-doc content must attach after that DOM exists (not via React
  children), and must survive re-renders of the markdown body.
- Standalone SVGs are currently shown as `<img src={svgDataUrl(...)}>`, which
  is fine to keep (an `<img>` of an SVG scales crisply via CSS transform) —
  _builder's call_ on `<img>` vs. inlining.
- Keep the security posture: don't inline untrusted SVG markup into the DOM
  if it wasn't already (standalone SVGs are currently isolated in an `<img>`).

## Left to the builder

- Whether to use a small library (e.g. a pan-zoom package) or a hand-rolled
  transform-based implementation. Prefer no new dependency if a ~150-line
  shared hook/utility does the job cleanly; one shared implementation should
  serve both the React standalone viewer and the post-render DOM attachment
  in markdown.
- Zoom step size for +/− buttons and per wheel notch.
- Exact control styling (match existing toolbar/button look in `styles.css`).
- Cursor feedback (grab/grabbing) during pan.
- Which in-markdown images qualify (e.g. skip tiny inline icons/badges).
- Distinguishing a drag from a click on images wrapped in links, whether
  pan/zoom also applies in Marks mode, and calling `preventDefault` on
  Ctrl+wheel over a zoomable element so Chromium's own page zoom doesn't fire.
